# 钓鱼玩法重做设计文档（竿影浮标 v2）

> 版本：v2 设计定稿 v0.1（待用户签字）
> 日期：2026-09-29
> 目标设备：FoloToy AI Passport（ESP32-C3 / 8MB Flash / 无 PSRAM / ST7789 240×320 / 三键共用 ADC GPIO0）
> 引擎：LVGL v9.5

---

## 0. 为什么重做（现有代码的真实评估）

读完 `main/fishing.c` / `fishing_logic.c` / `fishing_audio.c` / `main.c` 后结论：

**架构不糙，可保留**——
- 逻辑/UI/音频三层分离，`fishing_logic.c` 是平台无关纯状态机，有确定性 RNG（xorshift32，可注入种子单测），数据驱动钓点/饵料参数表。
- `fishing.c` 已用「按键回调只入队 → 独立 game_task 消费（20ms 循环）→ LVGL 加锁刷新」的正确范式，避开 LVGL 在中断/回调里被调用的坑。
- NVS 存最高分、电量节流读取都规范。

**真正糙、必须重做的只有两块**——
1. **画面**：天空/水面就是两个矩形，鱼竿/浮漂=一条线+一个圆，鱼=一个黄绿矩形「鱼影」。没有任何美术、没有动画（浮标只下沉一下）。
2. **玩法深度**：`STATE_BITE` 只是在随机窗口内「按一下 OK」的反应测试——没有收线技巧、鱼没有名字/尺寸/稀有度、没有关卡，玩两把就腻。

**重做策略 = 保留好架构 + 重做游戏设计（机制 / 内容 / 美术）**，不是推倒重来。

## 1. 美术方向（需求①）

### 风格定位
- **像素风（治愈系调性）**。参考：口袋妖怪图鉴（干净像素 sprite、复古界面）、星露谷（圆润治愈的氛围，但用像素块表达）。
- 为什么定像素风：设备只有 **240×320 且无 PSRAM**，扁平插画放大后边缘发虚、颜色发飘，反而显糙；像素风硬边 + 有限调色板在_low-res 屏上天生"对的"，是刻意的复古精致而非"没画完"。且仓库 `offline-pokedex` 已有 48×48 像素 sprite 管线，美术资源直接复用。
- 不做写实 3D、不做复杂粒子、不做渐变抗锯齿。**小尺寸像素 sprite + 平涂色块 + 少量动效**是正确且高效的方向。

### sprite 方案（沿用仓库已验证的图鉴范式）
- 图鉴（`docs/reference/sunny0826/offline-pokedex`）用 **48×48 预混合像素 sprite 嵌进固件**（`tools/gen_pokedex_static.py` 生成 C 数组，无白边）。
- 本玩法所有美术资产采用同一条管线：
  - 鱼：~28×18 像素（不同鱼形微调），每鱼一种调色板（≤8 色）。
  - 鱼竿/浮漂/水波/气泡/UI 图标：各自小尺寸 sprite 或 LVGL 基础图元 + 色块。
  - 生成方式：`ImageGen` 出**像素风干净插画** → 工具 downscale + 调色板量化成索引像素（≤8 色/鱼）→ 导出 C 数组（或直接手写小图）。封面与上架图同步走像素风以保持统一。
- **动效**（纯 LVGL 属性动画，零成本）：
  - 水面：正弦位移的水平高光线，每帧偏移（已验证无 PSRAM 也能跑 20ms 循环）。
  - 浮漂：咬钩时下沉 + 抖动；收线时随进度上下。
  - 鱼：咬钩瞬间从水下浮出 + 轻微摆尾（左右翻转两张帧或坐标微抖）。
  - 上鱼：鱼被拉出水面时缩小淡出 + 得分弹字。

### 三区布局（240×320）
```
┌────────────────────────┐  ← 天空区 (0..120) 柔和水蓝渐变 + 远山剪影 + 太阳
│   得分   最高   电量     │  ← HUD 顶栏（白字描边）
├────────────────────────┤
│   鱼竿弧线 + 鱼线        │  ← 中区 (120..200) 杆尖从左上伸出，线垂到浮漂
│   浮漂  ◉  气泡          │
├────────────────────────┤
│   水下区 (200..320)      │  ← 水蓝渐变 + 水波高光线 + 鱼影/鱼 sprite
│   收线绿条小游戏覆盖此区  │
└────────────────────────┘
```

## 2. 核心玩法循环（需求② 关卡 + 需求③ 鱼竿 + 把"无意义的点击"换成真技巧）

### 2.1 总循环状态机（取代现有 6 态）
```
  MENU(设置/图鉴/开始)
    │ OK
    ▼
  IDLE(本关场景就绪，显示场景名+目标)
    │ OK 抛竿
    ▼
  CASTING(抛竿动画 ~0.8s，浮漂落水)
    ▼
  WAITING(等待咬钩，时长由钓点+鱼竿决定)
    │ 咬钩
    ▼
  BITE(浮漂猛沉，进入收线小游戏)
    ▼
  REELING(★星露谷绿条收线小游戏★)
    ├─ 进度满 100% → CATCH(上鱼结算，含完美判定)
    └─ 进度归 0   → ESCAPE(跑鱼)
    ▼
  RESULT(展示鱼种/尺寸/得分 ~1.6s) → 回到 IDLE（同关继续，或达成目标进过关）
```

### 2.2 ★ 收线小游戏（把"窗口内按一下"换成技巧）
参考星露谷钓鱼条，完美贴合三键：
- 屏幕水下区有一条**竖直进度槽**，槽内有一个**绿色捕捉区（catch zone）**。
- 一条**鱼图标**在槽内上下乱窜（每条鱼有独立的移动速度/跳动幅度/节奏，由鱼种+鱼竿决定）。
- **按住 OK = 捕捉区上升；松开 OK = 捕捉区下落**（用现有 `BSP_BTN_PRESS`/`BSP_BTN_LONG` 释放检测，逻辑层已有按键事件）。
  - 进阶：UP/DOWN 可做微调偏移（可选，先不接，避免误触）。
- **鱼在捕捉区内** → 进度条上涨；**鱼在区外** → 进度条下跌。
- 进度涨到 100% = 钓上；跌到 0% = 跑鱼。
- **完美钓获（Perfect）**：全程鱼未离开捕捉区 → 额外加分 + 图鉴标记「完美」。

> 这套机制把"反应测试"变成"手眼协调 + 读鱼节奏"的真技巧，且**三键足够玩**（单键长按/松开即核心操作），与设备输入完全匹配。

### 2.3 鱼竿 / 钓法（需求③）—— 影响机制，不是纯摆设
| 鱼竿 | 抛程 | 捕捉区升降速度 | 鱼速缩放 | 提竿窗口 | 得分系数 | 定位 |
|---|---|---|---|---|---|---|
| 手竿 | 近（只够静水塘浅层） | 慢而稳（易控） | ×0.8（鱼慢） | 宽 | ×1.0 | 新手友好，容错高 |
| 路亚竿 | 中 | 中 | ×1.0 | 中 | ×1.3 | 配亮片饵，中大鱼 |
| 海竿 | 远（可够深海鱼） | 快（难控） | ×1.3（鱼快） | 窄 | ×1.8 | 高手向，高风险高回报 |

> 抛程决定"能遇到哪些鱼"（深海鱼需海竿才抛得到），捕捉区速度/鱼速决定难度，得分系数给回报——三竿形成清晰取舍。

### 3.2 饵料（沿用并扩充）
| 饵 | 作用 | 影响 |

### 3.3 关卡 / 多场景（需求②）
- **L1 静水塘**：默认解锁。目标：累计钓获 12 条 → 解锁 L2。
- **L2 急流河**：目标：钓获 20 条（含≥2 稀有） → 解锁 L3。
- **L3 深海**：目标：钓获 30 条（含≥1 传说） → 通关，解锁「钓鱼大师」称号与全图鉴挑战。
- 关卡推进以**累计捕获数 + 稀有度门槛**为 gate，数据驱动存 NVS。每关有场景专属背景色/水色与可达鱼池。
- 非硬性限时（避免挫败），但可加「每日挑战」可选计时模式（后期）。

## 4. 图鉴系统（需求④）

- 复用图鉴范式：**NVS 存每鱼捕获计数 + 是否完美**（24 种 → 每鱼 1 字节计数 + 1 bit 完美，极省空间）。
- 进入方式：主菜单「图鉴」→ 三键浏览：
  - UP/DOWN 单击：上/下一条；双击：跳 ±5；长按：跳到上一/下一场景首条（沿用图鉴交互范式）。
  - OK：查看详情页（sprite + 名称 + 体长 + 体重 + 稀有度 + 简介 + 已捕×N + 完美✓）。
  - 长按 OK：返回。
- 未捕获鱼显示「？？？」剪影 + 「尚未钓获」，保留探索感。
- 顶部显示「已收集 X/24」。

## 5. 蓝牙联机路线（需求⑤，Phase 4，PoC 门控）

- **硬件可行**：ESP32-C3 原生 BLE 5.0 GATT（≤3 并发）。
- **复用仓库已验证模式**：`docs/reference/shinku-chen/two-device-ble-link.md`（对称发现 + NimBLE + 可靠传输层，2026-09-18 已实测双板链路，约 60KB 堆开销）。
- **先做 PoC（门控）**：设备发现 + 配对 + 双方实时分数/已捕数同步，验证 BLE 栈与 LVGL+游戏同跑的内存余量。
- **PoC 通过 → 做完整联机**：60 秒倒计时「同场竞钓」，比谁钓得多/分高，结束互显战绩。
- **PoC 失败（内存/联调风险）→ 降级**：只做单机，联机留作标注「实验性功能」。
- 联机需两台设备真实验收（或 `bleak` Python 伪装机迭代协议），故排到最后阶段。

## 7. 分阶段交付（每阶段结束给可玩/可看产物，不一次性闷头做完）

- **Phase 0（本次）**：设计定稿 + 美术方向 + 新封面 → **交用户签字**。
- **Phase 1**：重做逻辑层（含单测通过），输出纯逻辑可验证（Python 对拍 `verify_logic.py`）。
- **Phase 2**：画面 UI 重做 + sprite + 中文字库，Simulator/真机截图预览。
- **Phase 3**：内容文案/音效/打磨 + 云端编译验收 + 用发布助手**更新**上架（project 700，补 changelog）。
- **Phase 4（挑战项）**：蓝牙联机 PoC → 完整联机 或 降级。

- [ ] 图鉴浏览/详情/未捕剪影/收集进度正常，捕获记录断电不丢。

## 9. 升级预设 / 前向兼容（为后续版本留好接口）

> **原则**：v2 只做 24 鱼 / 3 竿 / 3 关 / 单机，但**数据结构与存档必须从第一行就按"以后会变大"来写**——避免 v3 加内容时改存档格式、丢老玩家进度、或重排 ID 把图鉴搞乱。这一节的内容会写进 Phase 1 的验收清单，不是空话。

### 9.1 存档版本化（最关键）
- NVS 存一个整体 `save_blob_t`，首字段 `uint16_t magic` + `uint8_t schema_ver`（当前 = 1）。
- 读档时若 `schema_ver` 低于当前，走 `migrate_save(old, new)` 逐步升级；读不出/损坏则重置为新档（**不崩、不静默丢进度**）。
- 命名空间用 `fishing_v2`（已带版本），v3 自然用 `fishing_v3`，互不污染、互不误读。

### 9.2 内容表 ID 稳定 + 容量预留
- 每种鱼/竿/关卡有**不可变稳定 ID**（enum 从 0 顺序分配，新增只能**追加到末尾**，禁止重排或在中间插入）。
- 图鉴存储容量常量 `CODEX_CAP = 64`（当前仅用 24），用 `uint8_t caught[CODEX_CAP]` + `uint64_t perfect_bits` 存；新增鱼不挤爆、不搬数据。
- 数据表以 `FISH_COUNT` / `ROD_COUNT` / `LEVEL_COUNT` 常量驱动遍历，**所有代码按 `COUNT` 循环**，不写死 24/3/3。

### 9.3 内容版本号（与存档解耦）
- 定义 `CONTENT_VER`（当前 1）。鱼种/简介/数值调整只 bump 此号，不触发存档迁移（数值 tweak ≠ 格式变更）。
- 图鉴/关于页显示 `v2.CONTENT_VER`，方便玩家反馈"哪个版本钓到的 / 哪版改了什么"。

### 9.4 功能能力位掩码（feature flags）
- 定义 `uint32_t supported_features`，位定义：`BIT0 单机收线`、`BIT1 图鉴`、`BIT2 关卡`、`BIT3 蓝牙联机`、`BIT4 每日挑战`…… 当前置 BIT0/1/2。
- 用途：① 蓝牙联机（Phase 4）落地时置 BIT3，旧档/旧对端自动识别"对方不支持联机"；② 未来加「每日挑战 / 锦标赛」模式直接开位，不影响基础玩法；③ 给潜在的上架平台 / 伴生 App 做能力协商。

### 9.5 模式插件化（状态机可扩展）
- 主状态机保留 `MODE` 维度（当前 `MODE_SINGLE`）；未来 `MODE_VS`（联机对战）、`MODE_DAILY`（每日挑战）作为并列分支挂在 MENU 之后——**新增模式不改动现有收线 / 结算逻辑**。

### 9.6 美术 / 字库生成脚本参数化
- `tools/gen_sprites.py` / `gen_font.py` 以「内容清单文件」（如 `assets/content/fish_list.yaml`）为输入：**加一种鱼 = 在清单加一行 + 重跑脚本**，sprite / 字库自动扩，无需手工改数组。
- sprite 调色板约定 ≤8 色、尺寸档位固定，新增美术不撑爆预算。

### 9.7 多语言接缝
- 所有界面与简介文案走字符串表（当前 zh/en 两份 instructions 已分文件）；`content` 表加 `name_en` / `desc_en` 字段，未来加语言只加列、不动物理结构。

### 9.8 上架 / 版本展示位
- 封面与「关于」页预留版本位；发布时 `revisionId` 天然递增，更新走 project 700 的 `--auto` 更新流（已设计），**不新建玩法**。
- 变更日志（changelog）作为独立字段提交（已按平台要求分离），v3 起的更新只补 changelog，不污染简介。

### 9.9 升级预设落地检查（写进 Phase 1 验收）
- [ ] `save_blob_t` 含 `magic + schema_ver`，`migrate_save()` 存在且覆盖 +1 升级路径
- [ ] 图鉴容量 `CODEX_CAP ≥ 64`，ID 稳定不重排（新增只追加）
- [ ] 所有数据遍历按 `*_COUNT`，无魔法数字 24/3/3
- [ ] `supported_features` 位定义含联机 / 每日挑战预留位
- [ ] 内容清单文件驱动 sprite / 字库生成（gen 脚本参数化）
